# Multi-sensor HX711/HX717 load cells

Kaliru supports the COSMOS/SimpleAF `hx711s` and `hx717s` **host protocol** as
native Rust sensors. No Python or NumPy is loaded for these sensors. The driver
is ported from `pellcorp/kalico` at
`070a3066f2ffe1f0fdad291798263418b1c86004` (`klippy/extras/load_cell/hx711s.py`),
by James Turton, based on Gareth Farrington's HX711 driver (GPLv3).

This adds the downstream multi-sensor protocol to the existing Kalico load-cell
stack. It does not replace that stack with Pellcorp's older load-cell code.

## Firmware requirement

The MCU must already implement:

- `config_hx711s oid=%c sensor_count=%c gain_channel=%c`
- `add_hx711s oid=%c index=%c dout_pin=%u sclk_pin=%u`
- `query_hx711s oid=%c rest_ticks=%u`
- `query_hx711s_status oid=%c`
- `hx711s_attach_load_cell_probe oid=%c load_cell_probe_oid=%c`

COSMOS and Pellcorp's matching C MCU firmware implement this protocol. A native
Rust host can use that C firmware. Stock vendor firmware and upstream Kalico's
single-sensor `config_hx71x` protocol are insufficient. This change does not add
HX711s to Kaliru's Rust MCU firmware or flash any printer.

The MCU independently reads each chip, holds its latest reading, emits frames
at the first chip's cadence, and sums the channels for its local probe/filter.
Settling, stale-cell handling and the trigger watchdog remain MCU duties.

## Configuration

Both `[load_cell ...]` and `[load_cell_probe]` accept `sensor_type: hx711s` or
`hx717s`. Supply `dout_pins` and `sclk_pins`: comma-separated lists of **1–4** pin
pairs, in corresponding order, all on one MCU. Pin names are board-specific;
use the wiring for the actual printer, not pins from an unrelated example.

| Type | Sample rates | Gains/channels | Defaults |
|---|---|---|---|
| `hx711s` | 10, 80 | A-128, B-32, A-64 | 80, A-128 |
| `hx717s` | 10, 20, 80, 320 | A-128, B-64, A-64, B-8 | 320, A-128 |

HX711's rate must match the hardware RATE pin. All chips share the configured
rate and gain. The ordinary single-chip `hx711`/`hx717` drivers remain available;
SimpleAF's Ender 3 V3 SE/KE configurations use the single-chip `hx711` path.

### Calibration and secondary probes

Use Kalico's `LOAD_CELL_CALIBRATE` workflow. Kaliru follows its upstream Kalico
reference: `reference_tare_counts` has one value per channel. Use fresh calibration
on the actual hardware; do not copy another printer's values.

For a load cell alongside another primary probe, set `register_as_probe: False`
in `[load_cell_probe]` and use Kaliru's existing named-probe commands, for example
`PROBE PROBE=load_cell_probe` and `PROBE_ACCURACY PROBE=load_cell_probe`.
This port adds sensors to Kaliru's own probe stack, not compatibility with
SimpleAF's installer, command aliases or stored configuration.

## Software validation and remaining hardware work

`cargo test --locked --lib` includes sample-decoding vectors generated by the
unmodified reference driver's `_convert_samples`: 1–4 channels, signed ADC limits,
rounding and both latched error sentinels. Regenerate with:

```
python3 tools/hx711s_vectors.py /path/to/pellcorp/kalico > tests/data/hx711s.json
```

`tools/hx711s_compare.py` compares actual host startup/config commands with
Pellcorp's Python implementation in file-output mode. It covers all rate/gain
choices, invalid configurations, primary/secondary probes, and the SE single-cell
secondary-probe path. Secondary-probe command registries are queried over private
Unix sockets; the Rust process is checked for an absent `libpython` mapping.
See the script's usage and trace-helper requirements.

The test dictionary adds the downstream command formats to an existing STM32
dictionary. It validates host encoding, not MCU firmware execution. No physical
sampling, force-trigger latency, calibration accuracy, homing or bed meshing has
been validated by these tests. Hardware validation is required before treating
this port as ready for real nozzle contact.
